# IT Ticket Management API

## 1. Project Overview

IT Ticket Management API is a Python Backend portfolio project that simulates an IT Service Desk ticket management system.

The application will allow users to submit IT support tickets and provide a foundation for managing incidents and service requests.

The project is being developed as a simulated professional software engineering environment, using tickets, technical decisions, code reviews, Git, and GitHub.

**Current phase:** Minimum Viable Product (MVP).

## 2. Technology Stack

- Python
- FastAPI — REST API development
- Pydantic — data validation
- SQLite — relational database
- Git and GitHub — version control
- Bash/Linux — development environment

Additional technologies should not be introduced without discussing their necessity.

## 3. MVP Requirements and Decisions

- Ticket ID is generated by the system.
- User information is provided by the user.
- Ticket description is provided by the user.
- Minimum ticket description length: 10 characters.
- Ticket status is managed by the system.
- Ticket priority will be addressed in a later development phase.
- Technician assignment will be implemented later.
- Resolution timestamps will be implemented later.
- Tickets may initially exist without an assigned technician.

Ticket categories may eventually use predefined values such as network connectivity, application access, hardware, software, password, and account-related issues.

Do not assume that future features are already implemented.

## 4. Project Structure

Current and planned modules:

- `main.py` — FastAPI application and API endpoints.
- `database.py` — SQLite database operations.
- `models.py` — Pydantic models and validation.

The repository's actual code is the source of truth for implementation details.

## 5. Development Methodology

Development follows a ticket-based workflow.

Each task should have a clear objective and acceptance criteria.

The project owner is learning professional backend development and should write the code personally whenever possible.

AI assistants must:

1. Provide only one development step at a time.
2. Wait for confirmation before advancing.
3. Explain technical concepts and decisions.
4. Review code instead of automatically replacing it.
5. Ask questions when requirements are unclear.
6. Include occasional technical knowledge checks.
7. Avoid unnecessary complexity and overengineering.
8. Maintain the agreed MVP scope.
9. Treat technical questions separately from development progress.
